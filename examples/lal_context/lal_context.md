This matcher relies on Libadalang to identify a declaration or body in which the
region to identify lies, and stores a relative source location from the
beginning of said context entity. If the content of the context entity are
modified, the matcher will not return a match success, but report the cause of
failure (mismatch in context hash, mismatch in identifying names etc):

Given that the matcher needs to compute a hash from the context entity, it is
not well suited to be written by a human, and should instead be generated by the
library. This can be done using the command line tool:

```sh
stable_sloc_cli \
  --update='entry_name:lal_context:../pkg-child.adb:10:7:12:14:{message="some text"}' \
  --prefix=../ \
  --output=lal_entry.toml
```

In the above command line invocation, we request generating an entry with
identifier `entry_name`, using the `lal_context` matcher. It should designate
the region `10:7-12:14` in the file `../pkg-child.adb`. The last field is the
annotation to be attached to this new entry.

The `--prefix` option value will be stripped from the generated `file` entry
field, to allow matching the file from another location.

The generated entry looks like:
```toml
[entry_name]
at_most_once = true
file = "pkg-child.adb"
kind = "lal_context"
[entry_name.matcher]
context_hash = "16#64BB2695#"
end_col = 10
end_line = 9
sem_parents = [
"pkg.child",
"bar",
]
start_col = 3
start_line = 7
[[entry_name.annotations]]
message = "some text"
```

In which we can see:
- the file pattern `pkg-child.adb`,
- the name of the basic declaration used as context, in `sem_parents`
- the hash of the text of that basic declaration, in `context_hash`
- the designated source region range, relative to the start location of the
  context basic declaration.
- the optional `at_most_once` flag set to `true`, to indicate that this entry is
  meant to only match once.

Now if we attempt to match the entry on a modified version of the file, we
either get a success if the designated entity has not changed:

```sh
stable_sloc_cli --spec lal_entry.toml more_content/pkg-child.adb
entry_name: match SUCCESS
   more_code/pkg-child.adb:15:7 - 17:14
   Annotation:
      {"message":"some text"}
```

Or a failure should `Pkg.Child.Bar` have changed:

```sh
stable_sloc_cli --spec lal_entry.toml modified/pkg-child.adb
entry_name: match FAILED
   modified/pkg-child.adb
   Reason: Contents of <SubpBody ["Bar"] pkg-child.adb:3:4-10:12> changed
   Annotation:
      {"message":"some text"}

```

This matcher is not as expressive as other matchers, or an LKQL query, but can
uniquely identify a region, will always report a meaningful context, and can be
generated from an absolute source location span.
